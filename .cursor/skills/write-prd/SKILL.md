# Write PRD

> Author a one-page Product Requirements Document for a feature change.

## Trigger

- "draft a PRD"
- "write the PRD"
- "scope this out"
- "one-pager for this feature"

## When to use

- A feature touches more than one surface (UI + backend, LIFF + API).
- Success criteria worth recording before implementation.

## When NOT to use

- Tiny fixes — use a GitHub Issue only.
- Pure refactors — use `decision-log` instead.

## Process

1. Establish context — problem, user, why now.
2. Define one measurable goal.
3. In-scope behaviours (3–7 bullets).
4. Out-of-scope (explicit).
5. Acceptance criteria.
6. Dependencies and risks.
7. Rollout notes.
8. Open questions.

## Output

Short markdown PRD in `_documentation/` or `docs/` per project convention.
