# 雨の日の配信（雨の日クーポン）

雨の予報が出た日に、店舗の会員へその営業日だけ使えるクーポンやお知らせを送る機能。お知らせの「スケジュール配信」の種類（条件 ＞ 雨の日）の1つとして設定する。2026-11-01〜02 にユーザーと要件を決めた。

## 使い方（管理画面）

1. 「利用店舗」で店舗の座標を入力する。Google マップで店舗を右クリックして表示される「緯度, 経度」をそのまま貼り付けられる（例 `33.5494, 130.4242`）。
2. 「お知らせ ＞ スケジュール配信 ＞ 追加」で、配信の種類「条件」、タイミング「雨の日」を選び、店舗と閾値を入力する。
3. 届ける内容は、他のスケジュール配信と同じく「クーポンのみ」か「お知らせ（クーポン同時配布可）」から選ぶ。配るクーポンはスマレジにある既存のクーポン。
4. 「対象の条件」（セグメント）を指定すると、送る相手をさらに絞り込める。
5. 承認制の配信では、雨と判定されると承認のメールが届く。リンク先の「雨の日の判定結果」（スケジュール配信の一覧からも開ける）で「承認して送る」か「今日は配らない」を押す。

スケジュール配信はプロジェクトの管理者（本部）だけが登録・編集できる。承認は店舗の担当者もできる。

## 雨の日の設定

閾値は初期値を持たない必須入力。範囲外や、店舗の営業時間に収まらない値は保存しない。

| 項目 | 範囲 | 意味 |
|---|---|---|
| 店舗 | 選択中の店舗のうち利用中のもの | この店舗の座標の天気予報と営業時間で判定する |
| 降水確率 | 10〜100% | 1時間ごとの降水確率がこの値以上の時間を「雨」とする |
| 雨が続く時間 | 1時間〜営業時間の長さ | 雨がこの時間以上続くときだけ送る（にわか雨を除く） |
| 判定を始める時刻 | 開店の0〜3時間前 | この時刻から判定する |
| 送る締め切り | 閉店の何時間前（営業時間より短く） | この時刻を過ぎたら送らない |
| 週の上限 | 1〜7回 | 月曜〜日曜で数える。対象が0人だった日は数えない |
| 送る相手 | その店舗の会員 / 全会員 | 店舗の会員は `member_stores` の紐づき（入会店舗と、来店・注文などで関わった店舗）。セグメントを指定するとさらに絞り込む |
| 承認 | 送る前にメールで承認を求める（初期値） / 自動で送る | |

設定は `after_registration_deliveries.params` に保存する（`store_id` / `min_precipitation_probability` / `min_rain_hours` / `check_hours_before_open` / `cutoff_hours_before_close` / `weekly_limit` / `target` / `requires_approval`）。

## 判定

- `coupons:issue-weather` が15分ごとに動く。営業中は同じ配信を1時間ごとに判定し直す。
- 天気予報は OpenWeatherMap One Call 3.0 の1時間ごとの予報（48時間分）。約1km以内の地点は30分キャッシュする。
- 判定範囲は「開店（判定開始が開店前なら開店から） 〜 閉店」。営業中は現在時刻から閉店まで。範囲に入る分だけを分単位で数える（13:30 からなら 13時台は30分）。
- 次の場合は判定しない。
  - 休業日（定休日・臨時休業日。店舗ごとの上書きを含む）
  - 判定開始の前、送る締め切りの後
  - 利用停止の店舗、座標が未設定の店舗、無効の配信、停止中のクーポン
  - その営業日にすでに送った日、週の上限に達した日、「今日は配らない」を選んだ日

### 営業時間と営業日

- 営業時間は「時:分」。閉店が開店より前なら翌日の閉店（例 18:00〜03:00）、同じ時刻なら24時間営業。
- 日をまたぐ営業では、閉店前の深夜は前日の営業日として扱う。判定・期限・「1日1回」の日付はすべて営業日で数える。

## 承認制

- 雨と判定したら、送らずに承認を求めるメールを送る。
  - 宛先: その店舗の担当者と、プロジェクトの管理者のうち、お知らせの管理権限（`announcements.manage`）を持つ人。1人ずつ別のメールで送る。
  - メールには管理画面へのリンクだけを載せる。承認にはログインが必要。
- 承認の期限は30分（固定）。期限内に「承認して送る」を押すとすぐに送る。
- 期限が切れたら、その回は送らない。1時間後の判定でも雨なら、もう一度メールを送る。
- 「今日は配らない」を押すと、その営業日は判定もメールも止める。
- 他の店舗の担当者は承認できない。

## 送る内容

- クーポンのみ: クーポンを配る。「発行時に通知する」がオンなら通知する。
- お知らせ（クーポン同時配布可）: 送る相手全員を対象にしたお知らせを1件作り、通知する。クーポンを選んでいれば通知なしで同時に配る。
- 同じクーポンは1人1営業日1回まで。発行キー `weather_rain:営業日:クーポンID:会員ID` とデータベースの一意制約で守る。別のクーポンなら同じ日に複数届くことはある。
- クーポンの期限は配った時刻から営業日の終わりまで（通常は当日 23:59:59、日をまたぐ営業は翌日の閉店まで）。クーポン自体の終了日は超えない。
- 期限は会員側の画面で守らせる。期限切れ・使用済みのクーポンのコードはアプリに返さない。レジ（スマレジ）では期限を守らないため、店員がアプリの画面で期限を確認する。
- 送った後に新しく登録した会員にも、その営業日のうちは送る（登録処理のコミット後。失敗しても登録は止めない）。
- 対象の会員が0人なら送らない。
- クーポンを配った記録はクーポンの配信履歴に「雨の日自動配布」（`event_weather_rain`）として残る。手動の一括配布ではこの種別を選べない。

## データ

| テーブル・列 | 内容 |
|---|---|
| `stores.latitude` / `longitude` | 店舗の座標 |
| `after_registration_deliveries`（`schedule_type = weather_rain`） | 雨の日の配信。設定は `params` |
| `weather_coupon_runs` | 配信×営業日で1件。状態（`no_rain` / `awaiting_approval` / `expired` / `declined` / `sent` / `limit_reached` / `failed`）、最大降水確率、承認期限、送った人数 |

「雨の日の判定結果」で、送らなかった理由（雨の予報なし・週の上限など）を確認できる。

## 主なコード

- `app/Services/WeatherCouponService.php`: 判定・承認・送信・設定の確認
- `app/Services/ScheduledDeliveryTargetService.php`: 送る相手（店舗の会員 / 全会員 ＋ セグメント）
- `app/Services/Weather/OpenWeatherClient.php`: 天気予報の取得
- `app/Domain/Settings/ValueObjects/BusinessHours.php`: 営業時間と営業日
- `app/Domain/Weather/Policies/RainyPeriodPolicy.php`: 雨が続くかの判定
- `app/Console/Commands/IssueWeatherCouponsCommand.php`: 15分ごとのコマンド
- `tests/Feature/WeatherCouponServiceTest.php`

## 本番に出す前に

- 環境変数 `OPENWEATHER_API_KEY` を設定する（One Call by Call プランの契約が必要。1日1000回まで無料）。未設定でも既存機能には影響しない。
- マイグレーションを実行する。
- スケジューラー（`php artisan schedule:run` の毎分実行）が動いていることを確認する。
- 承認メールを送るため、メール送信の設定を確認する。
