# 配信の再試行と運用

## お知らせ通知

予約お知らせとスケジュール配信は、公開・クーポン発行と同じDBトランザクションで
`notification_pending` と `notification_retry_at` を保存する。
通知APIの成功後に未完了状態を解除する。例外または失敗件数がある場合は未完了のまま残す。
公開状態の `delivery_status=sent` は通知APIの成功を意味しない。

`announcements:retry-notifications` は毎分のLaravelスケジューラーから実行し、
未完了かつ再試行時刻を過ぎた通知を最大100件キューへ投入する。
通知ジョブはDBの条件付きUPDATEで5分間の処理権を取得するため、
同じ通知が重複してキューに入っても、処理権が有効な間は再送しない。
ワーカー停止やキューへの投入失敗でも、未完了状態が残り、定期処理で回復する。
期限切れワーカーの完了・失敗更新は、取得時刻が一致する処理権にだけ適用する。
通知を無効にした配信や、移行前のお知らせは自動再送しない。

配送保証は少なくとも1回。外部サービスへの送信とDB更新は一体でコミットできないため、
送信直後の停止や部分成功後の再試行では、成功済みの宛先にも再通知する場合がある。
API応答の失敗件数を無視して完了扱いにはしない。

## クーポン

予約クーポン配信は発行全体を1つのトランザクションで処理する。
途中の例外はロールバックしてワーカーへ伝え、最大5回再試行する。
再試行を使い切った場合に `failed()` で配信状態を失敗へ変更する。
クーポン発行通知ジョブはコミット後に投入し、ロールバックされた発行を通知しない。
同期実行では例外が呼び出し元へ伝わり、配信は失敗状態になる。

## 定期配信の予定と再試行

`deliveries:send-scheduled` は当日の配信時刻に観測した予定を
`scheduled_delivery_attempts` に永続化し、毎分、再試行時刻を過ぎた予定を最大100件処理する。
スケジューラーが停止していて観測できなかった過去の予定は補完しない。
登録後「分」配信は既存の登録時ジョブ、ランク到達配信は既存イベント処理を使用する。

予定は設定IDと予定日の組で識別し、配信内容と元の予定日時を保存する。
対象者の最初の取得に成功した後は宛先も保持する。
対象取得の失敗後も元の予定日を使う。再試行時点の会員属性を参照するため、
取得前に変更された属性まで過去の状態へ復元するものではない。
会員ごとの配信履歴は従来の一度限り・年単位・日単位のキーを維持する。
予定のキーと会員の配信キーを分けることで、前日の失敗が翌日の新規対象者を塞がない。

処理権はDBロック下で取得し、5分後に期限切れとなる。
完了・失敗更新は取得した試行番号と一致する行にのみ適用する。
停止した処理の引継ぎや部分成功後も、既存の会員別一意制約とトランザクションで
同じ配信キーの特典を重複発行しない。履歴の `sent_at` は実際に発行した日時を記録する。

最大5回試行し、失敗後は1・5・15・60分待つ。上限に達した行は
`failed_at` を保存して停止する。失敗行は調査用に保持し、自動削除・自動再開しない。
設定を無効化した場合は次の処理時に未完了予定を取り消し、削除した場合は外部キーで削除する。
配信内容の編集は既に保存した予定には反映されない。
1つの予定の対象取得・発行・完了記録が失敗しても、後続予定の処理を続ける。

追加テーブルはコード展開前にマイグレーションする。
このマイグレーションをロールバックすると保存した未完了予定・失敗記録を失うため、
復旧中の予定がある状態ではロールバックしない。

## スマレジ

同期APIが未完了を返した場合は既存mainの `release()` と `backoff` に従って
同じジョブを最大5回実行する。例外も非同期ワーカーへ伝える。
`ShouldBeUnique` のロックを保持したまま別ジョブを再投入しない。
同期ドライバでは従来どおり注文リクエストへ同期失敗を伝播させない。
本番で自動再試行を利用するには非同期キューとワーカーが必要。

## デプロイ

1. 新しいアプリコードを展開する前に追加マイグレーションを適用する。
   `php artisan migrate --force`
2. Laravelスケジューラーを毎分実行する既存の設定を維持する。
   `php artisan schedule:run`
3. ワーカーを再起動する。通知ジョブのタイムアウトは60秒なので、
   非同期キューの `retry_after` / visibility timeout はそれより長く設定する。
   `php artisan queue:restart`

旧コードも追加カラムのあるDBで動作するため、スキーマを先に反映できる。
この変更は既存のお知らせの通知結果を推測して再送するものではない。
