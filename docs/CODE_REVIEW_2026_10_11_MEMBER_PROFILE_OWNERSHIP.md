# 会員プロフィール更新の所有者確認

## 指摘 [P1]

`MemberService::updateProfile()` はキャッシュ済みの `$user->member` を参照し、保存時には会員IDだけでロックしていた。取得後に会員の所有者が変わると、旧ユーザーから新所有者の住所・追加項目を変更でき、元ユーザーの値を含む外部同期要求も記録できる。

## 修正

最初の取得はユーザーの現在の会員リレーションとプロジェクトで絞る。保存トランザクションではユーザーを先にロックし、同じプロジェクトの現在の所有会員をID指定でロックする。所有者変更・削除時は既存の会員未登録エラーで拒否する。ユーザー・会員・同期要求の保存前に照合することで、拒否時に部分変更を残さない。

既存の User → Member のロック順、論理削除スコープ、追加項目のマージ、同期要求の同一トランザクション保存を維持する。

## 検証

- 修正前：所有者変更2ケースが失敗、既存3テスト成功（10 assertions / 5.69s）。
- 修正後：プロフィール更新・外部同期・復旧の関連33テスト成功（167 assertions / 20.50s）。
- ロック取得直前に所有者変更または削除するケースで、元ユーザー・会員値が変更されず同期要求も作成されないことを確認。
- 保存時の所有者条件を隔離コピーから除去すると1テスト失敗、32成功（163 assertions / 20.69s）。
- 正しさ・可読性・設計・安全性・性能の独立した静的レビューでブロッカーなし。

外部API実接続は対象外。全ローカルCIとマージ対象HEADはPRに記録する。
