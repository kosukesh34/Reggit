# プロフィール同期の永続回復レビュー

## 問題と修正

会員プロフィールのローカル保存が成功してスマレジPATCHが失敗すると、次回の通常取得が古いスマレジプロフィールを取り込み、保存済み値を戻していた。初回回帰テストで Changed が Original に戻ることを確認した。

保存トランザクションで、会員ごとの変更項目・最新の送信内容・プロジェクト・顧客・契約・要求世代を永続化する。コミット後に送信し、失敗した要求を毎分最大100件再試行する。外部HTTP中にDBロックを保持しない。送信のリースと要求世代を分け、古いワーカーが新しい要求をACKできないようにする。期限切れワーカーが新しいACK後に完了した場合、同じ顧客・契約でのみ現在のローカル値を再送対象にする。

インバウンドGET開始前の要求世代とACK状態を記録し、適用時のロック下で再確認する。同期待ちやGET中に変化したプロフィールは取り込まず、独立したポイント同期は継続する。ロック順はユーザー→会員→送信予定に揃える。

部分更新は現在の変更項目と未送信項目に限定する。ACK済みの履歴全体を再送しない。住所の構造化項目を変更した場合は現在の各項目から組み立て、無関係な変更では未送信の自由入力住所を維持する。送信可能な項目が空でも古い要求を退役させ、値のクリア後に以前の値を再送しない。

## 検証

関連63テスト・241アサーション、Pint（9ファイル）、PHPStan（全対象・追加検証のみ1ワーカー）が成功。一時コピーで世代比較の条件を反転すると、古いGETがChangedをOriginalへ戻す回帰テストが失敗した。全ローカルCIはマージゲートで別途実行し、HEADと確定結果をPRに記録する。独立したアーキテクチャレビューが検出した空値、住所、契約変更、クロージャの不備を修正し、競合を含む回帰テストを追加した。

## 範囲と残る制約

- このPRは会員側プロフィール更新を対象とする。管理画面の更新は別途修正対象。
- 空の標準項目は既存ペイロードビルダーが送信しない。空bodyの退役は古い送信を取消す意味であり、外部側のクリア成功ではない。任意標準項目のクリア仕様と必須設定の扱いは別途修正対象。
- 外部APIには要求世代を条件とする更新がない。外部側の書き込み直後にプロセスが停止する全競合を完全には保証できない。
- 未設定の契約や外部で拒否される入力は正常ACKされず、再試行対象として残る。契約・顧客が変わった要求は旧送信先の作業として退役させる。
- 新規テーブルのマイグレーションと既存スケジューラの稼働が必要。
