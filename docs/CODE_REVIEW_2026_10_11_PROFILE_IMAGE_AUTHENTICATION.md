# プロフィール画像の現在認証・会員資格

画像更新・削除はcached Memberと取得済みUserで保存し、引き継ぎ後に認証世代が失効しても現在の画像を変更・削除できた。実UserServiceの端末認証→実Issue/Claim→古いUserの画像操作で2ケースを再現した。

既存public interfaceを維持して画像書き込みをprivate処理へ集約し、同じTXで現在Userの存在・project・認証世代と現在Memberをロック確認する。設定確認と旧path取得も現在モデルを使う。新規ファイル保存後のDB更新失敗は、その試行のファイルだけをcleanupして再throwし、TXは3回まで再試行する。旧画像は最外側commit後に削除し、削除例外はlogして保存済み新画像を維持する。包括的なfilesystem outboxは追加しない。

関連5クラス31テスト133アサーション成功。認証失効・会員削除／移管の拒否、DB保存失敗、旧画像削除失敗、外側rollback、現在世代の正常置換／削除を確認。一時コピーで修正を外すと10ケース失敗、正常1ケース成功。最終5軸レビューにブロッカーなし。Pint・全体PHPStanとコミット済み最新HEADの全ローカルゲートはPRへ結果を記録する。

外側TXのrollbackでは旧画像は維持するが、新規ファイルが孤立して残る制約がある。commit自体の失敗・プロセス停止・旧ファイル削除のfalse戻りも含め、DBとfilesystemの完全な原子性・永続再試行は保証しない。旧削除例外時は不要な旧ファイルが残る。今回の実証は制御した処理順序とfakeストレージで、実端末・本番・並列HTTP・外部実接続は未確認。
