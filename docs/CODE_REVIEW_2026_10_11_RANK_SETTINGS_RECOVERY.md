# ランク設定一括同期の復旧

## 問題 [P2]

設定保存後、外部ランクマスタ同期・会員の同期要求作成を同期実行していた。外部障害または走査途中の失敗では、保存済み設定に対する一括反映要求が残らず、会員単位の既存再送コマンドでも復旧しない。

## 修正と設計

設定とプロジェクト単位の同期要求を同一トランザクションで保存する。外側コミット後に即時試行し、毎分の既存再送コマンドで再開する。外部通信はロック外に置く。未設定連携は1時間後、障害は1分後に延期する。

要求UUIDと5分leaseを照合してランクIDだけを最新設定へ保存する。契約の変更は保存前・完了前に照合する。会員への要求は即時HTTPを実行せず永続化し、全走査成功後に一括要求を完了とする。途中失敗は次回再走査で補完する。

期限切れ旧ワーカーが外部状態を変更した可能性がある場合、最新要求の世代を更新して再送を残す。完了済みの要求行も保持し、進行中の新ワーカーによるACKが修復を消さない。lease解放はlease所有者だけを照合する。

外部ランク一覧取得失敗を空一覧扱いしない。削除失敗も例外とし、重複作成・誤った完了判定を防ぐ。

## 検証

修正前は保存済み設定の再送テストが失敗（1 failed / 4 assertions / 5.39s）。修正後は関連26テスト成功（115 assertions / 7.09s）。設定途中失敗、外側rollback、外部一覧/削除失敗、契約変更、旧ワーカーと新ワーカーの重なりを確認した。実DBへの2人目の要求保存を失敗させ、1人目の要求を保持して再送で両者を保存することも確認した。

修復時の世代更新を隔離コピーから除くと競合テストが失敗（1 failed / 22 passed / 92 assertions）。独立した5軸レビューで追加ブロッカーなし。Pint・PHPStanは成功。最新HEADの全ローカルCIはPRに記録する。

## 制約

新テーブルのmigrationが必要。外部処理は厳密一度実行を保証しない。旧ワーカーの一時的な外部変更を最新設定の再送で収束させる。外部API実接続・実端末・本番移行は未確認。既存の過去設定に要求を一括backfillしない。
