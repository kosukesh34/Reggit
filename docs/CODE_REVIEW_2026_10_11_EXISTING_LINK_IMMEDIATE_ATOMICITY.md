# 既存会員の即時連携: 契約と保存の整合性レビュー（2026-10-11）

## 問題と変更

管理画面のメール確認不要の既存会員連携は、外部検索後に契約が変わっても旧契約の会員を保存していた。また User 作成後の Member 作成失敗で User が残った。

メール確認不要の即時経路だけで、外部検索後に DB トランザクションを開始し、検索に使った契約と現在の契約を比較する。User と Member の保存を同じトランザクションに含める。外部検索はこのトランザクションの外に維持する。メール確認経路の captured contract 保存と確認時の再検証は維持する。

## 検証

- 変更前: 新規2テストが失敗（6 assertions / 6.21秒）。実際の設定 getter を使う API 部分モックで検索中に契約を変更すると旧契約の Member が作成された。Member creating イベントの失敗注入では User が残った。
- 変更後: ExistingMemberLinkTest / ExistingMemberLinkConfirmationRaceTest / SmaregiInboundCustomerPointsSyncTest の41テストが成功（189 assertions / 20.20秒）。
- 修正を一時コピーから外す mutation: 同じ2テストが失敗（6 assertions / 5.54秒）。リポジトリの修正は維持した。
- 正しさ・可読性・設計・安全性・性能の独立静的レビュー: blockerなし。git diff --check 成功。
- 隔離ローカル環境で Pint（6ファイル）と全体 PHPStan が成功。コミット後の全ローカルCIは指定マージゲートで別途実施し、対象HEADと結果をPRに記録する。

## 範囲

契約変更のテストは同一接続の制御されたインターリーブであり、実際の並行 HTTP リクエストやスマレジ実接続ではない。保存失敗は明示的な例外注入である。契約照合後からコミットまでの全設定変更を直列化する保証は追加していない。フロントエンド変更はなく、ブラウザーE2Eは追加していない。
