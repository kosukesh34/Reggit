# ウォレット残高取得の所有者確認

## 指摘 [P1]

`MemberWalletSummaryService::summarize()` はキャッシュ済みの会員を参照し、現在の所有者と削除状態を照合せずポイント・スタンプ・抽選権利の残高を返していた。所有者変更後の旧ユーザー、削除済み会員のキャッシュから取得できることを再現した。

## 修正

トランザクション内でユーザーの現在の会員リレーションをプロジェクト指定でロック取得し、そのロックを集計完了まで保持する。会員が見つからない場合は既存の401を返す。外部通信はなく、`getDisplayPoints()` の読み取り専用契約を維持する。ポイント台帳や残高キャッシュの修復は追加しない。

## 検証

- 修正前：所有者変更・削除の2ケース失敗、既存4テスト成功（22 assertions / 35.42s）。
- 修正後：6テスト成功（22 assertions / 35.19s）。API・抽選の関連範囲は29テスト成功（106 assertions / 37.57s）。
- 所有者制約を隔離コピーから外すと1テスト失敗、5成功（22 assertions / 37.08s）。
- 既存の並行ポイント更新と表示時のキャッシュ非更新を確認。
- 独立した5軸静的レビューでブロッカーなし。

外部API実接続・実端末は未確認。全ローカルCIの対象HEADと結果はPRに記録する。
