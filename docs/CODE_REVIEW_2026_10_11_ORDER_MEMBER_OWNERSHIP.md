# 注文由来の会員更新における所有者確認

## 指摘 [P2]

OrderRewardServiceはキャッシュ済みのuser.memberを来店記録・スタンプ・抽選付与に使用していた。所有者変更後に旧ユーザーの注文が別所有者の会員へ来店履歴を記録することを再現した。

## 修正

各操作がトランザクションを所有し、現在のユーザーの会員リレーションを注文のproject指定でロック取得する。操作完了までロックを保持する。論理削除済み・所有者変更済みの場合は既存の会員なし経路と同じく付与しない。Member → stamp/entitlementのロック順を維持し、外部通信を追加しない。

## 検証

- 修正前：来店誤記録の回帰テスト失敗（1 assertion / 5.39s）。
- 修正後：注文API・ポイント利用・新所有者テストの関連23テスト成功（99 assertions / 6.34s）。
- 通常来店、削除済みキャッシュ、取得直前の所有者変更、スタンプ有効条件での拒否を確認。
- 所有者制約を全3操作から除く隔離mutationで2件失敗。スタンプ操作だけの制約除去では誤ったaddStampsToMember呼出しを検出し1件失敗（22成功 / 99 assertions / 6.74s）。
- Pint・PHPStan成功。独立した5軸レビュー実施。最新HEAD全ローカルCIはPRに記録する。

外部API実接続は未確認。注文のポイント台帳処理・取消処理・ランク再計算は今回の変更範囲ではない。
