# ポイント取得中のローカル変更の保護

## 指摘と修正

スマレジのポイント取得開始時に注文が未同期でも、応答までに注文同期が完了すると既存のpending判定が消える。古い残高を適用して付与済みポイントを取り消す。同じ取得中に新規注文が作成・同期された場合も発生する。

取得前の表示残高と未同期状態を記録し、適用時のロック内で残高・未同期状態・顧客IDを再確認する。取得中の連携先変更ではプロフィールも適用しない。既存の台帳・注文repositoryを利用し、新しい汎用機構は追加しない。

## 検証

- 修正前: 2件失敗、12 assertions。ローカル100点が古い応答0点で取り消されることを再現。
- 修正後: SmaregiInboundCustomerPointsSyncTest全23件、80 assertions成功（7.87秒）。注文ACK、取得中の注文作成とACK、顧客ID変更を含む。
- Pint対象2ファイルと全PHPStan（1 worker）成功。
- 独立レビューで正しさ・可読性・設計・安全性・性能を確認、ブロッカーなし。
- 全CIはマージ時に最新HEADへ新規実行する。外部サービス実接続は未実施。

## 限界

残高が変化して元に戻る複合競合や外部POSTの応答消失による二重送信は、このsnapshotだけでは一般的に解決しない。本修正は再現した取得中のACK・残高変更・連携先変更を対象とする。
