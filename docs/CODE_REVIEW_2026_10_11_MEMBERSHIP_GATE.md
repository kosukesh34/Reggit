# 会員登録ゲートのライフサイクルレビュー

初回effectとliff-readyが同時に走ると、既存の会員管理側が登録APIの重複を抑えても、2回目のゲートが登録完了前に読み込みを終了する。本人確認・登録画面準備のawait後にcleanup確認がなく、画面離脱後にログイン表示や登録画面操作が行われる。またアプリ待機のタイマーがcleanup後にも残り、登録のPromise rejectionが未処理だった。

実行中を同期的にガードし、完了通知は一度に限定する。await後の副作用前に取消しを確認し、cleanupではタイマーと待機Promiseを終了する。登録モードと既存の会員管理APIは維持する。

実際のReactとフックをesbuildでbundleし、専用Chromiumコンテナで外部通信なしのローカルブラウザテストを実行した。修正前は6件中5件失敗、修正後は6ケースを各5回の計30回すべて成功。StrictMode、重複イベント、本人確認中と登録画面準備中の離脱、登録例外、タイマー終了を確認。TypeScriptとESLintも成功。独立レビューでブロッカーなし。

これはフックの実ブラウザ検証であり、LINE本番環境への実接続検証ではない。全ローカルCIと検証HEADはPRに別途記録する。
