# 削除済み会員のランク同期

会員ランクの再計算対象を取得した後に削除がcommitすると、syncのwithoutGlobalScopesが削除済み行を再取得し、ランク変更・履歴・到達配信を作成していました。ロック時のqueryにdeleted_at条件を追加し、削除済み会員は既存のfalse経路で終了します。

検証: 修正前は新回帰1件失敗・既存2件成功（30 assertions）。修正後3件成功・34 assertions、17.32秒。stale参照を使った削除後同期拒否、ランク保持、履歴・配信・お知らせ未生成を確認。独立5軸レビューでブロッカーなし。隔離ローカルDocker、外部API実接続なし。最新HEADの全チェックは指定merge-pr.shで実行します。GitHub Actions結果は使用しません。

設計判断: 会員ランクmoduleのsync interfaceで、ロック取得後の現在の会員状態を確認する。呼び出し元ごとの古い判定では削除競合を防げない。既存moduleに条件を集め、追加の抽象化は導入しない。
