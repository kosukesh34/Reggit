# 独自ドメインと HTTPS の設定手順（Elastic Beanstalk）

独自ドメインを取得済みのとき、Reggit-env をそのドメインで HTTPS 公開する手順です。  
ドメイン名は例として `app.example.com` と表記します。実際のドメインに読み替えてください。

---

## 前提

- Elastic Beanstalk 環境 **Reggit-env** は **負荷分散** になっていること。
- 独自ドメインの **DNS を編集できる**こと（Route 53 または他社 DNS）。

---

## 手順 1: ACM で証明書をリクエストする

1. **AWS Certificate Manager (ACM)** を開く（リージョン: **ap-northeast-3**）。
2. **「証明書をリクエスト」** をクリック。
3. **パブリック証明書** を選択 → **次へ**。
4. **完全修飾ドメイン名** に独自ドメインを入力（例: `app.example.com`）。  
   `www` 付きも使う場合は **「この証明書に別の名前を追加」** で `www.app.example.com` などを追加。
5. **検証方法**: **DNS 検証 - 推奨** を選択。
6. **キーアルゴリズム**: **RSA 2048** のまま。
7. **「リクエスト」** をクリック。
8. 証明書一覧で、作成した証明書の **ステータス** が **「検証保留中」** になる。
9. その証明書をクリック → **「DNS に CNAME レコードを作成」** または **「Route 53 でレコードを作成」** を表示し、**名前** と **値** を控える（または Route 53 の場合はボタンで自動作成）。

---

## 手順 2: DNS で証明書検証用 CNAME を追加する

### Route 53 でドメインを管理している場合

1. **Route 53** → **ホストゾーン** → 対象ドメインのゾーンを選択。
2. ACM の証明書画面で **「Route 53 でレコードを作成」** をクリックすると、検証用 CNAME が自動作成される。
3. 数分～最大 30 分ほどで ACM の **ステータス** が **「発行済み」** になる。

### 他社 DNS の場合

1. ACM の証明書詳細で表示される **CNAME 名** と **CNAME 値** をコピーする。
2. ドメインの DNS 管理画面で **CNAME レコード** を 1 件追加する。
   - **名前**: ACM の「CNAME 名」の表示どおり（多くの場合 `_xxxxx.app.example.com` のような形式。ドメイン部分は省略する場合あり）。
   - **値**: ACM の「CNAME 値」をそのまま。
3. 保存し、数分～最大 30 分待つと ACM の **ステータス** が **「発行済み」** になる。

---

## 手順 3: ドメインを EB のロードバランサーに向ける

### ロードバランサーの DNS 名を確認する

1. **EC2** → **ロードバランサー** を開く。
2. 名前が `awseb-e-...` や `awseb-...` で始まる、Reggit-env 用の **Application Load Balancer** をクリック。
3. **詳細** タブの **DNS 名**（例: `awseb-xxx.ap-northeast-3.elb.amazonaws.com`）をコピーする。

### Route 53 で A レコード（エイリアス）を作成する

1. **Route 53** → **ホストゾーン** → 対象ドメインのゾーンを選択。
2. **「レコードを作成」** をクリック。
3. 次のように設定する。
   - **レコード名**: 使いたいホスト名（例: `app` → `app.example.com`）。ルートなら空欄。
   - **レコードタイプ**: **A**
   - **エイリアス**: **オン**
   - **トラフィックのルーティング先**: **AWS のリソースへのエイリアス** を選択。
   - **リージョン**: **ap-northeast-3**
   - **ロードバランサーを選択**: 上で控えた **ALB** を選択。
4. **「レコードを作成」** をクリック。

### 他社 DNS の場合

- **CNAME レコード** を 1 件追加する。
  - **名前**: 使いたいホスト（例: `app`）。
  - **値**: ロードバランサーの **DNS 名**（例: `awseb-xxx.ap-northeast-3.elb.amazonaws.com`）。

※ ルートドメイン（`example.com`）で使う場合は、DNS 業者が ALB 向けの A レコードや CNAME フラット化に対応しているか確認してください。

---

## 手順 4: ロードバランサーに HTTPS リスナーを追加する

1. **Elastic Beanstalk** → **Reggit-env** → **設定** を開く。
2. **「インスタンスのトラフィックとスケーリング」** の **「編集」** をクリック（または、表示されている **「ロードバランサー」** カードの **「編集」**）。
3. **「リスナー」** のセクションを開く。
4. **「リスナーを追加」** をクリックし、次を設定する。
   - **ポート**: `443`
   - **プロトコル**: `HTTPS`
   - **SSL 証明書**: **ACM から証明書を選択** を選び、**手順 1 で発行済みになった証明書**（独自ドメイン用）を選択。
5. **「変更を適用」**（または「追加」→「適用」）をクリックする。
6. （任意）**ポート 80（HTTP）** のリスナーで **「HTTPS へリダイレクト」** があれば有効にすると、`http://` でアクセスしても `https://` に転送される。

環境の更新が完了するまで数分かかることがあります。

---

## 手順 5: APP_URL を独自ドメインの HTTPS に更新する

1. **Elastic Beanstalk** → **Reggit-env** → **設定** → **更新、モニタリング、ログ記録** の **「編集」**。
2. **環境プロパティ** で **APP_URL** を、独自ドメインの **https** に変更する。  
   例: `https://app.example.com`
3. **変更を適用** する。

スマレジの「利用者契約通知先URL」「Webhook送信先」も、この **https://app.example.com** ベースの URL に変更してください。

---

## 確認

- ブラウザで **https://（あなたのドメイン）** を開き、アプリが表示され、証明書が有効であることを確認する。
- 必要に応じて **docs/ENV_PRODUCTION_TEMPLATE.md** のベースURL・スマレジのURLを、新しいドメインに合わせて更新する。

---

## まとめ（チェックリスト）

| # | 作業 |
|---|------|
| 1 | ACM で独自ドメイン用の証明書をリクエスト（DNS 検証） |
| 2 | DNS に検証用 CNAME を追加 → 証明書を「発行済み」にする |
| 3 | ドメインの A レコード（または CNAME）を EB のロードバランサーに向ける |
| 4 | EB のロードバランサーに HTTPS 443 リスナーを追加（発行済み証明書を選択） |
| 5 | 環境プロパティの APP_URL を `https://（独自ドメイン）` に更新 |

問題があれば、ACM の証明書ステータス・DNS の伝播・ロードバランサーのリスナー設定を順に確認してください。
