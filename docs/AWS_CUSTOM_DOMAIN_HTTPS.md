# 独自ドメインと HTTPS の設定手順（Elastic Beanstalk）

独自ドメインを取得済みのとき、Reggit-env をそのドメインで HTTPS 公開する手順です。  
ドメイン名は例として `app.example.com` と表記します。実際のドメインに読み替えてください。

---

## 今すぐやること（証明書が「保留中の検証」のとき）

**reggit.shop** の証明書を **「発行済み」** にするには、**DNS に CNAME を 1 件追加**するだけです。

1. **ACM コンソール**（ap-northeast-3）で該当証明書を開く → **「CNAME 名」** と **「CNAME 値」** をコピー。
2. **お名前.com** → ドメイン **reggit.shop** → **DNS 設定** を開く。
3. **CNAME** を 1 件追加する。
   - **名前**: CNAME 名の `_xxxxxxxx.reggit.shop` の **`_xxxxxxxx` の部分だけ**（例: `_4d7d4abf835ca072a2a7a1b4a1922fc9`）。
   - **値**: CNAME 値を**そのまま**（例: `_a6f2a12812xxxx.acm-validations.aws.`）。
4. 保存し、**5〜30 分** 待つ。ACM のステータスが **「発行済み」** になったら、下記「手順 3」以降（ドメインを ALB に向ける → HTTPS リスナー追加 → APP_URL 更新）に進む。

---

## 前提

- Elastic Beanstalk 環境 **Reggit-env** は **負荷分散** になっていること。
- 独自ドメインの **DNS を編集できる**こと（Route 53 または他社 DNS）。

---

## 手順 1: ACM で証明書をリクエストする

1. **AWS Certificate Manager (ACM)** を開く（リージョン: **ap-northeast-3**）。
2. **「証明書をリクエスト」** をクリック。
3. **パブリック証明書** を選択 → **次へ**。
4. **完全修飾ドメイン名** に独自ドメインを入力（例: `app.example.com`）。  
   **`https://www.reggit.shop` でアクセスする場合は、必ず「この証明書に別の名前を追加」で `www.reggit.shop` を追加する。** 追加しないとブラウザで `ERR_CERT_COMMON_NAME_INVALID`（この接続ではプライバシーが保護されません）が出る。
5. **検証方法**: **DNS 検証 - 推奨** を選択。
6. **キーアルゴリズム**: **RSA 2048** のまま。
7. **「リクエスト」** をクリック。
8. 証明書一覧で、作成した証明書の **ステータス** が **「検証保留中」** になる。
9. その証明書をクリック → **「DNS に CNAME レコードを作成」** または **「Route 53 でレコードを作成」** を表示し、**名前** と **値** を控える（または Route 53 の場合はボタンで自動作成）。

---

## 手順 2: DNS で証明書検証用 CNAME を追加する

### Route 53 でドメインを管理している場合

1. **Route 53** → **ホストゾーン** → 対象ドメインのゾーンを選択。
2. ACM の証明書画面で **「Route 53 でレコードを作成」** をクリックすると、検証用 CNAME が自動作成される。
3. 数分～最大 30 分ほどで ACM の **ステータス** が **「発行済み」** になる。

### 他社 DNS（お名前.com など）の場合

1. **ACM の証明書詳細**で **「CNAME 名」** と **「CNAME 値」** をそのままコピーする（画面に表示されている通りに。末尾のピリオドも含める場合あり）。
2. ドメインの DNS 管理画面で **CNAME レコード** を 1 件追加する。
   - **名前（ホスト）**: ACM の「CNAME 名」から **あなたのドメイン部分を除いた** 部分だけを入力する。  
     - 例: CNAME 名が `_4d7d4abf835ca072a2a7a1b4a1922fc9.reggit.shop.` なら、お名前.com の「名前」には **`_4d7d4abf835ca072a2a7a1b4a1922fc9`** だけを入力（`.reggit.shop` は入力しない。管理画面が自動で付与する）。
   - **値（行き先・参照先）**: ACM の「CNAME 値」を **そのまま** 入力（例: `_a6f2a12812xxxx.acm-validations.aws.`）。末尾の `.` は DNS によっては不要な場合あり。エラーになったら末尾を除いて再試行。
3. **TTL** は 300 や 600 のままで可。**保存** する。
4. **5〜30 分** ほど待つと ACM の **ステータス** が **「発行済み」** に変わる。すぐ変わらなくても最大 72 時間程度かかることがある。

#### お名前.com で reggit.shop の CNAME を追加する手順（要点）

1. **お名前.com** にログイン → **ドメイン** → **reggit.shop** を選択 → **DNS 設定／DNS レコード設定** を開く。
2. **「レコードを追加する」**（または CNAME 追加）をクリック。
3. **タイプ**: **CNAME** を選択。
4. **名前（ホスト名）**: ACM に表示されている CNAME 名の **`_xxxxxxxx.reggit.shop` の `_xxxxxxxx` の部分だけ** を入力（`_4d7d4abf835ca072a2a7a1b4a1922fc9` のような形式）。
5. **値（参照先）**: ACM の **CNAME 値** をそのまま貼り付ける（`_xxxx.acm-validations.aws.` のような形式）。
6. 保存後、ACM コンソールで証明書のステータスを **数分ごとに更新** して「発行済み」になるまで待つ。

### 30分〜2時間以上経っても「発行済み」にならないとき

1. **CNAME が正しく解決されているか確認する**  
   ターミナルで次を実行（または [https://dnschecker.org](https://dnschecker.org) で `_4d7d4abf835ca072a2a7a1b4a1922fc9.reggit.shop` の CNAME を検索）:
   ```bash
   dig CNAME _4d7d4abf835ca072a2a7a1b4a1922fc9.reggit.shop +short
   ```
   **期待する結果**: `j88b.jkddzztszm.acm-validations.aws.` のような値が 1 行で返ること。  
   何も返らない・別の値・エラーなら、DNS の設定か伝播に問題がある。

2. **ホスト名の二重付けに注意（お名前.com）**  
   お名前.com では「ホスト名」に **ドメインを含めない** ことが多いです。  
   - **NG**: `_4d7d4abf835ca072a2a7a1b4a1922fc9.reggit.shop` と入力すると、自動で `.reggit.shop` がさらに付き、`_4d7d4abf835ca072a2a7a1b4a1922fc9.reggit.shop.reggit.shop` になり検証に失敗します。  
   - **OK**: ホスト名には **`_4d7d4abf835ca072a2a7a1b4a1922fc9` だけ** を入力する。  
   いまのレコードでホスト名が `_4d7d4abf835ca072a2a7a1b4a1922fc9.reggit.shop` になっている場合は、**いったん削除**し、ホスト名を **`_4d7d4abf835ca072a2a7a1b4a1922fc9` のみ** で作り直す。

3. **値の typo を確認**  
   ACM の「CNAME 値」と完全一致しているか確認（余計なスペース・末尾の `.` の有無はプロバイダの説明に従う）。

4. **ACM のリージョン**  
   証明書は **ap-northeast-3** でリクエストしているか確認。別リージョンだと EB では使えません。

5. **再リクエスト**  
   上記を直しても 24 時間以上変わらない場合は、ACM でその証明書を削除し、同じドメインで **証明書をあらためてリクエスト** すると、新しい CNAME 名・値が表示されます。新しい値で DNS を追加し直す。

### DNS は解決しているのに ACM が「発行済み」にならないとき

**確認**: 次のコマンドで CNAME が返れば、DNS は正しく設定されています。
```bash
dig @8.8.8.8 CNAME _4d7d4abf835ca072a2a7a1b4a1922fc9.reggit.shop +short
```
（証明書ごとに CNAME 名は異なります。ACM の画面の CNAME 名に読み替えてください。）

- **まだ待つ**: ACM の検証は数分〜**最大 72 時間**かかることがあります。DNS が正しければ、あと 30 分〜1 時間で「発行済み」になる場合が多いです。ACM コンソールで証明書を開き、**ブラウザで更新（F5）** してからステータスを確認してください。
- **すぐ HTTPS を有効にしたい場合の代替: メール検証**  
  1. ACM で **いまの証明書を削除**する。  
  2. **「証明書をリクエスト」** で同じドメイン（例: reggit.shop）を入力し、**検証方法で「メール検証」** を選んでリクエストする。  
  3. ドメインの管理者メール（whois のメールや `admin@reggit.shop` など）に届く **検証メールのリンクをクリック**する。  
  4. 検証完了後、数分で **「発行済み」** になる。  
  メール検証の証明書も ALB の HTTPS で利用でき、**更新時は 45 日前にメールが届く**ので、そのリンクをクリックすれば更新されます。DNS 検証のように「CNAME を置いたまま自動更新」ではありませんが、すぐ発行されるメリットがあります。

## 手順 3: ドメインを EB のロードバランサーに向ける

### ロードバランサーの DNS 名を確認する

1. **EC2** → **ロードバランサー** を開く。
2. 名前が `awseb-e-...` や `awseb-...` で始まる、Reggit-env 用の **Application Load Balancer** をクリック。
3. **詳細** タブの **DNS 名**（例: `awseb-xxx.ap-northeast-3.elb.amazonaws.com`）をコピーする。

### Route 53 で A レコード（エイリアス）を作成する

1. **Route 53** → **ホストゾーン** → 対象ドメインのゾーンを選択。
2. **「レコードを作成」** をクリック。
3. 次のように設定する。
   - **レコード名**: 使いたいホスト名（例: `app` → `app.example.com`）。ルートなら空欄。
   - **レコードタイプ**: **A**
   - **エイリアス**: **オン**
   - **トラフィックのルーティング先**: **AWS のリソースへのエイリアス** を選択。
   - **リージョン**: **ap-northeast-3**
   - **ロードバランサーを選択**: 上で控えた **ALB** を選択。
4. **「レコードを作成」** をクリック。

### 他社 DNS の場合

- **CNAME レコード** を 1 件追加する。
  - **名前**: 使いたいホスト（例: `app`）。
  - **値**: ロードバランサーの **DNS 名**（例: `awseb-xxx.ap-northeast-3.elb.amazonaws.com`）。

※ ルートドメイン（`example.com`）で使う場合は、DNS 業者が ALB 向けの A レコードや CNAME フラット化に対応しているか確認してください。

#### ルート（reggit.shop）も開けるようにする（お名前.com）

お名前.com では **ルートに CNAME は設定できない** ため、次のいずれかで対応する。

**方法 A: A レコードでルートを ALB の IP に向ける**

1. ALB の IP を確認する（変わる可能性があるため、変更時はお名前.com で A レコードを更新する必要あり）:
   ```bash
   dig www.reggit.shop +short
   ```
   最後の 2 行が IP（例: `13.208.119.14`, `16.208.30.246`）。
2. お名前.com → reggit.shop → **DNS 設定** → **レコードを追加**。
3. **タイプ**: **A**
4. **ホスト名**: **空欄** または **@**（ルート用）
5. **値（IP）**: 手順 1 の **1 つ目の IP** を入力（例: `13.208.119.14`）。
6. 保存し、**同じホスト名（空欄 or @）で A レコードをもう 1 件追加**し、**2 つ目の IP**（例: `16.208.30.246`）を入力。  
   （1 つの IP だけでも動作するが、ALB は複数 IP を持つため 2 つあるとよい。）
7. 数分後に **https://reggit.shop** でアクセスできるか確認する。

**方法 B: お名前.com の「URL 転送」で reggit.shop → www.reggit.shop に飛ばす**

- お名前.com の **「URL 転送」** や **「ドメイン転送」** で、**reggit.shop** を **https://www.reggit.shop** に転送する設定が可能なら、ルートに A レコードを置かずに済む。  
- 設定後は **reggit.shop** にアクセスすると自動で **www.reggit.shop** に飛ぶ。

#### reggit.shop で「このサイトにアクセスできません」「DNS_PROBE_FINISHED_NXDOMAIN」が出る場合

**原因**: 証明書検証用の CNAME（`_4d7d...`）だけでは、**reggit.shop そのもの**はどこにも向いていません。**サイト用**のレコード（reggit.shop → ALB）が別に必要です。

**対処**: お名前.com の DNS で、**reggit.shop を ALB に向ける**レコードを 1 件追加する。
- **レコードタイプ**: CNAME（ルートで CNAME が使えない場合は A レコードや ALIAS 等、お名前.com の案内に従う）
- **ホスト名**: 空欄（ルート `reggit.shop` の場合）または `www`（`www.reggit.shop` の場合）
- **値（参照先）**: **EC2 → ロードバランサー** で Reggit-env 用 ALB の **DNS 名**（`awseb-xxxxx.ap-northeast-3.elb.amazonaws.com`）をコピーしてそのまま入力

追加後、数分〜最大 1 時間で reggit.shop が開くようになります。

## 手順 4: ロードバランサーに HTTPS リスナーを追加する

1. **Elastic Beanstalk** → **Reggit-env** → **設定** を開く。
2. **「インスタンスのトラフィックとスケーリング」** の **「編集」** をクリック（または、表示されている **「ロードバランサー」** カードの **「編集」**）。
3. **「リスナー」** のセクションを開く。
4. **「リスナーを追加」** をクリックし、次を設定する。
   - **ポート**: `443`
   - **プロトコル**: `HTTPS`
   - **SSL 証明書**: **ACM から証明書を選択** を選び、**手順 1 で発行済みになった証明書**（独自ドメイン用）を選択。
5. **「変更を適用」**（または「追加」→「適用」）をクリックする。
6. （任意）**ポート 80（HTTP）** のリスナーで **「HTTPS へリダイレクト」** があれば有効にすると、`http://` でアクセスしても `https://` に転送される。

環境の更新が完了するまで数分かかることがあります。

---

## 手順 5: APP_URL を独自ドメインの HTTPS に更新する

1. **Elastic Beanstalk** → **Reggit-env** → **設定** → **更新、モニタリング、ログ記録** の **「編集」**。
2. **環境プロパティ** で **APP_URL** を、独自ドメインの **https** に変更する。  
   例: `https://app.example.com`
3. **変更を適用** する。

スマレジの「利用者契約通知先URL」「Webhook送信先」も、この **https://app.example.com** ベースの URL に変更してください。

---

## 確認

- ブラウザで **https://（あなたのドメイン）** を開き、アプリが表示され、証明書が有効であることを確認する。
- 必要に応じて **docs/ENV_PRODUCTION_TEMPLATE.md** のベースURL・スマレジのURLを、新しいドメインに合わせて更新する。

## まとめ（チェックリスト）

| # | 作業 |
|---|------|
| 1 | ACM で独自ドメイン用の証明書をリクエスト（DNS 検証） |
| 2 | DNS に検証用 CNAME を追加 → 証明書を「発行済み」にする |
