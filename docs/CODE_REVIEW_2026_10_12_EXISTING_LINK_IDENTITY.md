# 既存会員連携の応答ID検証

## P1: 申請対象と異なる外部会員を連携できる

確認処理は申請に保存した会員IDで外部APIを呼ぶが、取得した配列のcustomerIdを照合していなかった。重複確認は申請側ID、保存は応答側IDで行うため、9001の申請に9002が返ると既に連携済みの9002も保存できた。

応答IDが文字列または整数で、文字列化した値が申請対象と厳密に一致するときだけ処理を続ける。欠落、空値、配列、不一致は既存の業務例外で拒否する。外部取得は引き続きDBトランザクションの外側に置く。

## 検証

隔離Docker/MySQLでExistingMemberLinkTest全23件・138アサーション成功。追加の5ケースは通常ユーザーとゲスト、不一致・欠落・空値・配列を検証し、申請が未確認であること、会員数・ユーザー数・既存ポイントが変化しないことを確認する。最終HEADの全ローカルCIはPRに記録する。

## 継続調査

別ユーザーが同一外部会員を同時確認する場合、申請・User単位のロックだけでは直列化できない。外部会員IDを保存する登録復旧・inbound同期も含めて所有権の保証方法を検討する。このPRは競合対策を完了したとは扱わない。
