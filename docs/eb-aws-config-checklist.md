# Elastic Beanstalk（Docker）AWS 側設定チェックリスト

アプリが本来 5 秒程度で返るのに 504 になる場合、**リクエストがアプリに届いていない**可能性があります。以下を確認してください。

## 1. ロードバランサー → プロセスの「ポート」（最重要）

**パス**: 環境 → 設定 → ロードバランサー → プロセス（デフォルト）→ 編集

- **ポート**: **80** であること。
  - EB Docker では **ホストの nginx が 80 で待ち受け**、その中でコンテナの 8080 にプロキシします。
  - ここが **8080** のままになっていると、ALB はインスタンスの **8080** に送りますが、ホストでは 8080 をリッスンしていないため、**接続がハングして 60 秒でタイムアウト**し、504 になります。
- **プロトコル**: HTTP（または HTTPS リスナーの場合は HTTPS）
- **ヘルスチェック パス**: `/health`
- **正常とみなす HTTP コード**: `200`

## 2. リスナー（ALB）

**パス**: 環境 → 設定 → ロードバランサー → リスナー

- ポート 80（と 443）のルールで、転送先が「デフォルトプロセス」など正しいターゲットになっているか確認。

## 3. ターゲットグループ（EC2 コンソール）

**パス**: EC2 → ターゲットグループ → （EB 環境に紐づくターゲットグループ）→ ターゲット

- 登録されているポートが **80** であること（インスタンスのポート = 80）。
- ターゲットのヘルスが「健全」であること。
- ヘルスチェックのパスが `/health`、期待コード 200 になっているか。

## 4. セキュリティグループ

- **インスタンス用 SG**: インバウンドで **80** を ALB 用 SG（または適切な送信元）から許可していること。
- **ALB 用 SG**: インバウンドで 80/443 を 0.0.0.0/0 など必要な送信元から許可していること。

## 5. まとめ

| 設定場所           | 確認項目     | 想定値 |
|--------------------|--------------|--------|
| EB プロセス        | ポート       | **80** |
| EB プロセス        | ヘルスパス   | `/health` |
| ターゲットグループ | インスタンスのポート | **80** |

**ポートが 8080 になっている**場合、これが「5 秒で返るはずなのに 60 秒で 504」の典型的な原因です。80 に修正して環境を更新してください。
